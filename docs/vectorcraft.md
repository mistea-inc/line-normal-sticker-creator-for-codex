# VectorCraftの操作

一次資料は [公式リポジトリ](https://github.com/storytold/vectorcraft)、[制御プロトコル](https://github.com/storytold/vectorcraft/blob/main/docs/control-protocol.md)、[文字とレタリング](https://github.com/storytold/vectorcraft/blob/main/docs/typography-lettering.md)。未確認のコマンド名や引数を推測しない。

## 接続

このプロジェクトはGUIのループバック制御チャネルを使う。既存のグローバルMCP設定を書き換えずに操作できる。

`launch` が作品専用のポートを選び、専用プロファイルと読み書きルートを設定する。接続先は作品の `state.json` に記録する。固定した開発者のホームディレクトリやポートへ接続しない。

`Client.call(method, params)` はネイティブ要求と応答を作品のログへ保存する。`Client.execute(command, **params)` は `engine.execute` を呼ぶ。同じインスタンスへの編集は順次実行し、現在の文書を確認する。

コマンド一覧や引数は実行中バージョンのAPIと公式文書で確認する。アプリの更新で挙動が変わった場合は、まず試験文書で保存・再読込・出力を検証する。

## 編集可能な文字

`Client.phrase` は1つの語句を、文字本体・内側フチ・外側フチの3つのテキストオブジェクトとして作り、語句単位のグループへまとめる。書体、色、サイズ、座標、縁取り幅、傾き、曲線、縦書きを引数で指定する。

複数の語句を使う場合は、それぞれの語句グループを「セリフ全体」へまとめる。レイヤーの手前から、文字、内側フチ、外側フチになることをGUIで確認する。

日本語UIの基準位置によるずれを避けるため、ヘルパーは `leadingModel=romanBaseline`、`charAlign=romanBaseline` を明示している。

## フォント

`text.fontList` で利用可能なフォントとスタイルを確認し、実際に選ぶ。`text.fonts` の結果に代替、欠落、未解決の文字がある場合は出力を完了扱いにしない。

フォントを追加する場合は配布元と利用条件を確認し、原画や衣装の設定と同様に記録する。追加するフォントは専用プロファイルの `Fonts` にコピーし、`text.rescanFonts` で再読込できる。OSの全体設定を変える前に、作品内の範囲で対応する。

## 保存とレビュー

`Client.open` は既に開いているタブを探して再利用する。未保存の編集があるタブをファイルから開き直して置き換えない。

人間の完了報告を受けた `review-complete` は、未保存の変更を同じファイルへ保存してから承認のハッシュを記録する。出力処理は、その承認と一致するソースだけを使用する。

インポート警告やリンク切れがある場合は解消する。透過表示の切り替えなど表示操作でも文書が変更扱いになる場合があるため、`document.inspect` の `dirty` を確認する。

## 起動と描画の問題

接続拒否、GUI未表示、フォント不足、PNGの不正な余白は別々に調べる。作品の `logs/` を確認し、必要な工程だけを再実行する。起動の問題を理由に原画やレビュー済みデータを作り直さない。

描画確認は作品とは分けた文書で、VectorCraftのネイティブ操作を使って行う。作成したPNGとGUIスクリーンショットを実際に開いて確認する。試験用図形の成功だけで、スタンプのデザインを検証済みにしない。
